# 0.8 自定姓名、战场火势与人物武学设计

状态：用户于2026-10-24确认“可以，就这样”，现已完成0.8.0源码与Windows本地包。433项单测、TypeScript、生产构建、本地服务、开发版及离线包桌面/两种手机布局验证通过；独立最终审查无未解决P0/P1/P2。用户原始要求：首次进入手动输入主角姓名；所有角色可放火，地形影响成功率，风象影响火势，天气影响熄灭；每位有名人物拥有依经历设计的专属武学，关系好或被击败后有概率传授。以下数值为已确认首版参数。

## 1. 方案选择与范围

推荐完整接入现有格子战斗：共有放火行动＋战场天气风向＋独立人物武学＋请教/切磋传授。既能让普通人放火，又能让周瑜的火神具有独特效果。沿用现有速度行动队列、每人每轮一次移动和一次行动、五人出战、亲密度及天下日结。

另外两种方式：只做即时火伤，工作量较小但没有风向蔓延；只让特殊武学放火，较容易平衡但不满足人人可放火。因此不采用。

本版覆盖当前47位具名人物：历史人物目录37位、孙坚孙策2位、地方官员8位。卑弥呼继续仅供资料查看，拥有武学介绍但不开放相遇/切磋/传授；其余人物沿用当前相遇年代和实际驻地。阿满、陈达、无名军士和山贼保留基础行动，不冒造历史专属武学。山狼等动物不能使用人为点火；动物仍承受火伤并避火。

这是一次0.8整体升级；姓名、火势和武学分模块实施，完成联合验收后更新Windows本地包。美术沿用现有人物图，火焰/风向使用程序绘制。

## 2. 首次姓名输入

- 新游戏先显示姓名面板，确认后进入序章。输入框初始为空，有可访问的标签、手机键盘和Enter提交；空白姓名不能继续。
- 首尾空白清除，允许2—8个Unicode字符，限汉字、字母、数字、间隔点；拒绝控制符、HTML和纯标点。界面以文本节点绘制，不将姓名作为HTML插入。
- 主角始终用`traveler`作为稳定ID，姓名存入`heroName`。所有主角名字、资料/队伍/成长、战场/结算、叙事发言、同行人简介中的姓名引用经统一显示函数读取，不修改全局静态人物表，不变更画像路径。
- 旧档首次升级也补录一次姓名，保留当前年月、旅程、队伍、关系、经济、天下和战斗阶段。确认前暂停继续游戏，不能因取消输入而重建旧档；确认后刷新不再询问。
- 后续“重新开始”创建新档时重新命名；普通读档不改名字。未完成命名的界面用“旅人”作临时称呼，不自动写死“姜垣”。

## 3. 战场天气与风象

每场开战生成并保存环境，桌面和手机都能看到天气、风向、风力与下一次变化节点。八方向箭头表示火势吹去的方向，例如“东南风，吹向西北”；不能只显示含义容易相反的箭头。

- 天气有晴、阴、雾、小雨、暴雨、雪。按游戏月份给季节权重：夏季雨天较多，冬季可下雪，其他月份不生成雪。
- 风向八方向加静风，风力无风/微风/强风。静风时风力为0。
- 每个完整轮次结束结算一次环境，30%概率更换风向/风力；每3轮有25%概率改变天气，仍受月份限制。先按本轮环境结算火，再更新并显示下轮环境，玩家行动期间不偷偷变天。
- 此处是玩法天气，并非汉末真实每日气象复原。与旅行“雨阻”及NPC战略战报区分，不让一次战斗多次推进天下日历。

## 4. 人人可用的放火行动

任何存活的人类战斗单位在自己的行动中可选择“放火”，点选自身格或八邻格中的一格；可先移动再放火。放火不消耗移动次数，但消耗本次行动，失败同样消耗。界面选格时显示目标地形和最终成功率。敌方人类也能放火，AI只在有战术收益时使用。

| 目标地形 | 基础点燃率 | 最长燃烧轮次 |
| --- | ---: | ---: |
| 道路/普通空地 | 35% | 2 |
| 森林 | 75% | 4 |
| 木桥 | 60% | 3 |
| 倾覆木车 | 65% | 3 |
| 岩石/石墙/水面 | 0%，不可选 | 0 |

天气乘数为晴1、阴0.9、雾0.8、小雨0.5、暴雨0.15、雪0.35，最终概率取整到百分比。强风增加10个百分点，上限95%；火神单独加成见下文。不可燃地形始终0%，不会被加成点燃。已经着火的格子禁止再次点火，不消耗行动。自身格和森林格使用同一公式，地形决定差异。

木桥、木车本版燃烧后留下焦痕，保持原有通行性，避免改变桥梁路网而产生无路可走的残局。焦痕格本场不能再次燃烧；森林燃尽后变成焦地、移动代价1且不再提供树林远程掩护。新一场战斗恢复原地图。

## 5. 火势蔓延、熄灭和伤害

每个火格记录位置、火势1—3级、剩余轮次和来源单位ID。普通点火从1级开始；每轮森林火在强风下有35%概率升一级，最多3级。

每轮末使用固定顺序和本轮开始时的火格快照：

1. 按天气尝试熄灭；每个火格独立计算。晴10%、阴20%、雾25%、小雨55%、暴雨90%、雪70%。熄灭只移除火，不给尚有燃料的格子生成“已燃尽”标记。
2. 未熄灭火格烧伤所在单位，敌我一视同仁。火势1/2/3级分别伤害最大生命的8%/10%/12%，向上取整且至少2点，忽略护甲和守势。火势伤害可以击倒，兵团以现有池化生命同步降低兵力和攻防。
3. 向八邻格尝试蔓延，每个旧火格最多成功点燃两格，新火本轮不再扩散/伤害。风向按“吹去方向”计算：顺风基础45%、侧风15%、逆风5%；静风各方向15%。强风顺风加20个百分点、微风不加。再乘目标地形基础点燃率/75%和天气乘数，限制0—95%。不可燃、已有火、焦痕和越界格跳过；多个火源不能给同格叠火或重复伤害。
4. 旧火剩余轮次减1，为0则烧尽并转换焦地/焦痕；新火按目标地形取得寿命，初始1级。随后检查胜败和下一轮行动者。

移动路径必须真实检查火格；一次移动只要经过火格便额外受一次8%最大生命（至少2点）火伤，按经过的最高火级使用8%/10%/12%，不按路径长度反复叠加。中途被击倒停在首个致命火格，不能继续攻击。地面余火本身就是持续烧伤，本版不再叠一套离开火格仍持续扣血的状态。

场上同时全灭判玩家败，与现有优先检测己方全灭一致。胜败发生即停止轮次推进，不允许多次结算奖励。

AI考虑直接攻击、武学、放火和避火路线；优先直接可击倒目标，不在无收益时烧自己，不让狼放火。火神范围施放同样可能引火伤友，没有免疫或自动识别敌我的魔法火焰。

## 6. 武学归属、学习与装配

- 每位具名人物先天掌握自己的专属武学，出战时可实际施展。主角通过请教或战胜人物学到相应秘籍。
- 已学武学永久记录，显示名称、师承、取得途径、效果、冷却、取材依据；主角最多装配3种，战外随时更换，学习数量不限。人物自身武学始终占其专属位，不与旧有“拼命/绝处逢生”替换。
- 一次主动武学消耗行动，除标注位移外不额外扣移动次数；不能同回合施放后再普通攻击。普通“拼命/绝处逢生”原有规则保留，但同一次伤害不能无限重复叠加增益。
- 首版不加内力条、秘籍背包物品、售卖或武学升级。每种武学施放后冷却3个完整轮次，每场重新开始冷却；火神也受相同冷却。已装配的主角与拥有该武学的NPC按同一规则使用。
- 同名效果不叠加，护持/减伤上限50%，伤害增益上限50%，移动增益上限2格，所有临时效果在标定轮次到期或战斗结束时清理。

### 效果模板

基础攻击伤害继续按攻击、护甲、格挡、视线和闪避规则计算。人物武学不能无视石墙、射穿巨石或击中越界格。

| 模板 | 可执行效果 |
| --- | --- |
| 破击 | 按当前武器合法距离和视线攻击一次，攻击力×1.5；最终伤害仍考虑目标防御、掩护、格挡、闪避 |

| 疾行 | 移动至路径代价不超过本单位移动力+2的空格，树林按原代价；不穿人、不穿墙，途中照常受火伤，施放即结束行动 |

## 7. 关系请教与战胜传授

人物详情增加武学卡：专属秘籍、当前亲密、是否已学、传授概率、冷却/可用原因。

### 关系请教

- 亲密度达到80，且当前可真实交往（同城相遇或已同行），可选择“请教武学”。不要求先招募，不能隔城向出征人物请教。
- 消耗1日，每位老师每个游戏日最多1次；学习概率30%，亲密100时50%，中间按每点1个百分点线性增长。失败保留亲密，显示对方此次未传授。
- 按耗时动作现有逻辑推进天下，判定资格在行动开始时检查；若这一天结束后人物移动，已经开始的请教可完成，不能重复从旧城再次点击。
- 请教先持久化随机判定和日期再展示结果，关面板、刷新或重复点击不能重抽；已学后不再收费/耗时。

### 切磋与战胜

- 增加“切磋”入口，在当前可真实交往的人物详情中发起，亲密不设门槛；卑弥呼和只读无名士兵不开放。已同行人物也能切磋，参战教师不会同时出现在己方。
- 主角与老师进行1对1格子战斗，玩家使用自己的等级/属性/已装配武学。老师等级取`min(10, max(3, 主角等级+2, 老师已同行成长等级))`，用该老师真实武器和专属武学，临时构造，不修改队伍成长。
- 开始即消耗1日并记入本次挑战；战斗使用相同放火、风象与天气规则，切磋伤势不带入日常。败北/撤退不传授、不删除老师，也不改城池归属。
- 胜利后以40%概率传授该老师的专属武学，亲密不足80也可获得；不额外再抽一次关系传授。已学秘籍不重复发放，明确提示已掌握。
- 切磋不给普通战斗经验、物资、任务旗标或招募奖励，避免反复刷经验。重新挑战要走新的合法挑战入口和耗时流程，不能调用普通“重试”绕过日期与抽取记录。
- 任何以后真实出现的具名敌人战败也使用相同结算接口，按被击败人物逐个判定；当前NPC战略模拟攻城不是玩家亲手打败，不自动发秘籍。
- 学习结果在战斗结束时一次性持久化，返回人物详情/城池，不能流入原护送任务或结局场景。

## 8. 存档与运行时边界

新增独立姓名模块、武学目录/学习状态模块、战场环境/火势模块；战斗引擎负责合法行动、伤害、轮次和胜败。UI只调用规则函数，不能凭按钮禁用代替后端校验。

- `heroName`与命名确认字段；旧档缺失时保留原档并进入补录状态。
- `martial`记录已学秘籍、主角装配、每老师请教/挑战日期、独立持久随机种子与已结算记录。47人物映射全覆盖，未知秘籍ID/重复装配/非法冷却/未来日期拒绝。
- `activeBattle`为有版本的完整快照，包含遭遇身份、切磋老师、出战名单、战斗单位/临时状态、环境、火格、焦痕、行动队列、轮次及随机种子。每次合法玩家行动或敌方行动后保存，在AI动画前后刷新都从已完成动作继续。
- 校验战场坐标、地形、火势级别、剩余轮次、单位来源与当前遭遇匹配；损坏新增数据单独备份并提示恢复，保留基础玩家进度，不直接将整份旧档当坏档重开。
- 0.7旧战斗没有快照时保留原有从该遭遇开局恢复规则，首次加载后立即保存新快照。命名补录在恢复场景前完成。
- 学习随机流与NPC天下/旅行随机流隔离，避免打开人物面板改变攻城或旅行事件。只读操作不抽取随机数、不走日历。
- 现有兵团按生命折算兵力；火伤/护持同样走统一生命更新，不能使兵团血量、存活人数、攻防脱节。

## 9. 交互与验收

战斗侧栏增加“攻击/放火/武学/守势”；选择技能或火格可取消回普通选择，轮到敌方时不可操作。放火高亮可选格，武学显示目标类别、范围、冷却；地图火势需可辨识但不遮挡人物/生命，地形说明包含当前火势和剩余轮次。战斗日志明确失败点火、蔓延、熄灭和火伤来源；环境阶段即使无人攻击也刷新胜败。

人物详情与主角成长面板均能查看秘籍；学习提示清楚显示成功/未获传授/已掌握，不用仅图标传达。手机390×844及横屏844×390无横向溢出，触屏能够命名、选格、装配、请教、切磋和返回。

实施按测试先失败后实现：

1. 名字验证、中文/Unicode边界、HTML拒绝、旧档补录、全界面主角引用。
2. 地形点燃率差异、失败耗行动、非当前角色/动物/水面/越界拒绝，移动后点火合法。
3. 固定种子下风向/风力差异、六天气熄灭、火快照不当轮无限连烧、重复火源不叠伤、燃尽焦地及桥通行。
4. 敌我火伤、途中致命火伤、兵团伤亡同步、环境杀死最后一人和同时全灭。
5. 全47秘籍映射、固有武学、主角装配3种、合法范围/视线/冷却、辅助不可复活、增益封顶与清理。
6. 请教80门槛、100概率、真实同城、已同行、出征拒绝、失败扣日、重复点击/刷新不重抽、已学不消耗。
7. 切磋1对1、教师身份/武学、低亲密胜后传授、败/退无奖励、无任务串线、一次结算、老师仍存活和驻地不变。
8. 新旧档、战斗快照及损坏数据恢复；开火/蔓延/学到秘籍后刷新保持，已有0.7天下与旅行不回退。
9. 全量单测、TypeScript/生产构建、本地服务测试；实际桌面/手机流程与屏蔽外网Windows本地包验证。
