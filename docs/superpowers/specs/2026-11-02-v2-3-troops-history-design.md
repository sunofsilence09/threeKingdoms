## 主角领兵与计算

1. 保留每角色1000兵和五人出战；在军务、队伍和主角详情间补清晰入口，显示配兵所需的预备兵及不可操作原因。不会自动赠送士兵或重复开发第二套库存。
2. 新战斗使用统一的领兵攻防模块。输入包括人物成长、天赋和羁绊计算后的六维、存活兵数、兵种与士气。人物本体与士兵贡献分开展示，受伤后按真实存活人数重算。
3. 建议初始平衡：士兵攻击贡献ceil(N/10)×[1+0.02×max(统率−10,0)+0.01×max(武力−10,0)]；士兵防御贡献ceil(N/40)×[1+0.02×max(统率−10,0)]。加上人物本体后再使用既有士气、武学、兵种技能修正。N为当前存活兵数。
4. 带兵双方的伤害采用攻击×100/(100+防御)的防御折算，再处理掩护、守势、技能、闪避，避免人数增加后固定减防导致伤害长期只剩1点。纯人物单挑保留当前人物战斗规则。
5. 城市守军的棋盘战斗适配与新部队使用相同士兵尺度；预览、普通攻击、武学、兵战技和敌方AI共用规则，不能只改详情数字。守军展示明确区分总兵力与人物六维。
6. 主角战略攻城目前已能率预备兵出征，本次保留其独立的天下围攻规则，不把棋盘战斗数值直接套进战略结算。界面说明两种战斗方式。
7. 新增战斗规则版本标记；已保存的旧战斗保持原数值与结算，到下一场启用新算法。继续维护配兵/卸兵/伤亡守恒和重复结算保护。

2. 时间资料逐条核对《三国志》及《三国演义》相关纪传/回目；史实、演义和游戏编排分别标记。只知道年份或季节的事件明确显示精度，游戏触发月不冒充公历精确发生月。
3. 所有推进日期的动作走统一时钟触发事件，跨多月/多年的长时间动作按顺序记录全部跨过的节点；每事件每局一次，刷新不能重复发奖励。
4. 地图显示最新大事和未读数量，提供“历史大事”回顾面板，可按年代及来源查看背景、涉及人物/地区和参与结果。多事件合并成通知队列，不能用连续弹窗堵塞长时间推进。战斗期间不打断当前行动。
5. 为讨董、官渡、赤壁、夷陵等关键节点增加护送、筹粮或援助支线。玩家可在相关城邑、对应时间窗口内选择参加或继续行旅；明确标价、耗时、奖励和截止条件。参与可影响军需、铜钱、好感及本局事件记录，奖励每项只发一次，错过仍可回顾。
6. 历史记录描述参考史事；本局参与状态单独记录。参与人物已经离世、阵营或城池状态不符时，显示无法参与的原因，不复活人物、不强制交割玩家城池。
7. 旧档升级补齐当前日期之前的大事作为历史回顾，不追发旧奖励或强迫重演。未来节点正常触发，进度严格保存。
